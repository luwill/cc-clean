# 确认清单、操作与恢复

## 最小计划

计划应保存在任务工作目录，私密文件权限 0600。用实际路径填充，不把例子中的字段和目录自动变成删除名单。

```json
{
  "scenario": "retire-inaccessible-account",
  "environment": {
    "config_dir": "实际配置目录",
    "state_file": "已核实的主状态文件",
    "credential_scope": "准确命名空间；未验证则明确标注"
  },
  "preserve": ["实际保留的配置、项目、Skills、插件、MCP 与路由路径"],
  "operations": [
    {
      "action": "remove-json-fields",
      "path": "实际主状态文件",
      "fields": ["逐项确认的旧账号字段"],
      "before_sha256": "执行前预期内容指纹",
      "evidence": "字段与目标旧账号关联的本地证据",
      "impact": "需要重新登录或重新拉取对应缓存"
    }
  ],
  "backup": "已验证备份位置、文件与凭据分别说明",
  "verification": ["未选 JSON 字段一致", "保留文件及链接一致"],
  "authorization": "引用本聊天中实际授权，不能由 agent 编写一句已确认代替用户批准"
}
```

逐文件删除的计划记录完整路径和原指纹，不用 `rm -rf ~/.claude`、`find -delete` 或在运行时展开的 glob。旧 backup 可能包含身份和 Key，但不因此自动可删；先加入单独清单。全量重置、抹除项目历史和卸载属于更大的范围，必须对应用户要求与确认。

账号关联证据分清：缓存 email 命中、标识同值、凭据 payload 的账号信息、实际路由认证来源。`device_id` 存在只证明客户端有此字段，不能断言服务器已经接收或用它封禁。不要重新生成硬件 ID、伪装设备地区或承诺“清理后是新设备”。

主状态中的 `deviceId` / `device_id` / `deviceID`（含嵌套）默认只记录元数据并保留。报告的结构序号不含真实祖先键名，也不确认账号归属；它只用于审阅。清理前重新解析当前文件，在本地确认真实字段路径及影响，绑定源指纹、验证备份，再取得用户对具体字段的确认。没有字段时不补造，不按值形似 UUID 扩大删除范围。

## 文件变更

1. 核对计划及现有授权；确认备份完整、足够私密且恢复样本通过。准备工作先完成，最终执行确认针对具体结果。
2. 确认目标环境会话正常退出、没有写入者。若进程取证会读取环境，使用本地过滤器仅输出允许字段，绝不把原始 `ps eww` 结果交给模型。没办法确认写入状态时可以交计划和验证过的备份，暂停依赖静止状态的操作。
3. 对每次文件改动重查原指纹；源数据变化则停止该操作，保留已经完成的回执。对新增记录/目标重新核对和备份，不用旧指纹强行覆盖。
4. JSON 按 key 删除，仅改变批准路径。保持其他值语义一致，并保留源权限、属主及相关 ACL/xattr；macOS 可先用 `ditto --rsrc --extattr --acl` 克隆源文件到同目录的受限临时文件，再写新内容、fsync、原子替换。不要把原 JSON/token 打印到终端。
5. 逐项记录成功、失败与未开始，随后比较不在操作范围内的文件/链接。任何异常只报告具体范围，失败后不扩大清理。

辅助脚本产出的 manifest 含源路径、文件 hash、符号链接目标和基础权限信息，本身也私密。备份文件可能是原秘密的完整副本，不代表消除了泄露风险。macOS native copy 请求了 ACL/xattr 保留，但 helper 仅验证字节、mode、uid/gid 和链接目标；有额外元数据要求时补原生验证，不能声称已经全量校验 ACL/xattr。

## 输入历史里的密钥

先按 JSONL 逐行解析，在本地内存中用已授权的密钥来源做精确匹配。默认不使用“像密钥”的正则直接删历史，也不在命令参数、计划、日志或正文里写秘密值。提供记录行号、字段名、匹配计数、拟用替换标记即可。

定点替换后验证：行数一致；每行仍可解析；未选行字节一致；选中行其他字段和值一致；批准的原字符串匹配数变为预期值。JSON 转义字符串要解析后定位再映射到原始 span；不要对整个文件 `json.dumps` 重写。无法可靠定位时停止提出更小的编辑方法，不模糊匹配。

还在运行的会话可能覆盖替换或追加数据，因此写入前核对静止状态。脱敏不撤销密钥，也不能证明之前没人读过副本。是否轮换须结合真实暴露迹象和用户范围；不自动调用供应商服务。

## 采集开关

删除留存文件不等于关闭未来采集。用户要求设置开关时再核对当前官方 environment variables / data usage / remote control 页面，说明指标、错误报告和其他网络请求各自影响。不同变量的非空值语义、功能影响及版本可能不同，不能沿用某一版本一概而论。用户未要求时不要改 `.zshrc` 或 settings。

## 恢复

先运行 helper `verify`（不要加 `--check-source`，清理后源当然会不同）。从备份复制指定文件到独立恢复目录进行核验，确认要恢复哪些字段、凭据和历史。真正覆盖现有环境之前再次核对作用范围与用户授权，保留恢复前现状；不要自动全量覆盖新的登录或路由设置。恢复旧历史/凭据会重新带入被清理的数据。

对 helper 文件备份中的精确普通文件，使用 [review.md 的恢复计划与回执](review.md#恢复计划与回执) 保存已验证的恢复前备份，生成逐文件 before/intended-after 指纹，并在外部授权恢复之后检查所选与全部未选项。helper 不恢复、不确认授权，也不代替 Keychain 或字段级恢复的专项验证。

## 验收报告

写实际完成项、备份位置/验证范围、保留项比较、会话/路由状态、未验证项、恢复路径。离线文件一致性、Keychain 内容变化、一次在线请求成功分别给结论；不要升级为账号一定正常、所有 MCP 均可用、全局零残留或服务器已删除。
